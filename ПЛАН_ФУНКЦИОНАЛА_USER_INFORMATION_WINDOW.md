# План добавления функционала в UserInformationWindow

## Обзор
Окно `UserInformationWindow` в настоящее время отображает только статическую информацию. План предусматривает добавление функционала для клиентов банка, позволяющего им просматривать информацию о своих счетах и выполнять базовые операции.

---

## Этап 1: Подготовка данных и интеграция с JSON-сервисом

### 1.1. Добавление зависимостей
- **Файл:** `View/UserInformationWindow.xaml.cs`
- **Действия:**
  - Добавить `using SimpleBank.Models;`
  - Добавить `using SimpleBank.Services;`
  - Добавить поля:
    - `JsonDataService _dataService`
    - `BankData _bankData`
    - `List<Client> _clients`
    - `List<BankAccount> _accounts`

### 1.2. Инициализация данных
- **Метод:** Конструктор `UserInformationWindow()`
- **Действия:**
  - Инициализировать `_dataService = new JsonDataService()`
  - Загрузить данные через `LoadData()`
  - Восстановить связи между счетами и клиентами

### 1.3. Метод загрузки данных
- **Метод:** `LoadData()`
- **Действия:**
  - Загрузить `BankData` из JSON через `_dataService.LoadFromJson()`
  - Инициализировать `_clients` и `_accounts`
  - Восстановить связи `BankAccount.Owner` по `OwnerPassportData`
  - Обработать ошибки загрузки (если файл не существует, использовать пустые данные)

## Этап 2: Система идентификации клиента

### 2.1. Модель для идентификации
- **Вариант A (Простой):** Использовать паспортные данные для поиска клиента
- **Вариант B (Расширенный):** Создать окно авторизации клиента (аналогично `AuthorizationWindow`)
  - Модель: `ClientAccount` (паспортные данные + PIN-код)
  - Сервис: `ClientAccountService` для управления аккаунтами клиентов

### 2.2. Окно авторизации клиента (если выбран вариант B)
- **Файл:** `View/ClientAuthorizationWindow.xaml` и `.xaml.cs`
- **Функционал:**
  - Поле ввода паспортных данных
  - Поле ввода PIN-кода (или пароля)
  - Кнопка "Войти"
  - Кнопка "Назад"
  - Валидация данных

### 2.3. Модель аккаунта клиента (если выбран вариант B)
- **Файл:** `Models/ClientAccount.cs`
- **Свойства:**
  - `PassportData` (string)
  - `PinCode` (string)
  - `FullName` (string)
  - Атрибуты `[DataContract]` и `[DataMember]` для сериализации

### 2.4. Сервис аккаунтов клиентов (если выбран вариант B)
- **Файл:** `Services/ClientAccountService.cs`
- **Методы:**
  - `AuthenticateClient(string passportData, string pinCode)` - аутентификация
  - `CreateClientAccount(string passportData, string pinCode, string fullName)` - создание аккаунта
  - `IsPassportExists(string passportData)` - проверка существования

## Этап 7: История операций (опционально, расширенный функционал)

### 7.1. Модель операции
- **Файл:** `Models/Transaction.cs`
- **Свойства:**
  - `TransactionId` (string) - уникальный идентификатор
  - `AccountNumber` (string) - номер счета
  - `TransactionType` (enum: Deposit, Withdraw, Transfer)
  - `Amount` (decimal) - сумма операции
  - `TransactionDate` (DateTime) - дата и время операции
  - `Description` (string) - описание операции
  - `TargetAccountNumber` (string) - для переводов

### 7.2. Обновление BankAccount
- **Добавить:**
  - `List<Transaction> _transactionHistory`
  - Метод `AddTransaction(Transaction transaction)`
  - Метод `GetTransactionHistory()`

### 7.3. Вкладка "История операций"
- **Элементы:**
  - `DataGrid` для отображения операций
  - Колонки:
    - Дата и время
    - Тип операции
    - Сумма
    - Описание
    - Номер целевого счета (для переводов)
  - Фильтры:
    - По типу операции
    - По дате (от/до)
    - По сумме (от/до)

### 7.4. Интеграция операций в существующие методы
- **Обновить методы в `BankAccount`:**
  - `Deposit()` - добавлять транзакцию типа Deposit
  - `Withdraw()` - добавлять транзакцию типа Withdraw
  - `Transfer()` - добавлять транзакции для обоих счетов

## Примечания

1. **Простота реализации:** План начинается с простых функций и постепенно усложняется
2. **Обратная совместимость:** Все изменения должны быть совместимы с существующим функционалом
3. **Учебный проект:** Фокус на изучении WPF, работы с данными, сериализации
4. **Модульность:** Каждый этап может быть реализован независимо
5. **Расширяемость:** Архитектура позволяет легко добавлять новый функционал
